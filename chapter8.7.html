Maintaining a Change Log

The Change Log is the project's single source of truth for every change that was proposed, approved, rejected, or implemented. A complete change log provides an audit trail for compliance, post-implementation reviews, and future planning.

Single Source of Truth Audit Trail

What to Record for Every Change Request

After a change request is closed (whether approved and implemented, or rejected), add an entry to the change log containing the following fields:

Field Description Example
Change ID Unique identifier (e.g., CR-001) CR-042
Date When the request was submitted 2026-04-23
Requester Name of the person who submitted it J. Doe
Description Brief summary of what was proposed Update authentication library
Impact Assessment Summary of timeline, budget, and risk analysis +2 days, no budget change, medium risk
Decision Approved, Rejected, or Deferred Approved
Approver Name of the Change Authority or CAB S. Smith (PM)
Implementation Date When the change was deployed (if approved) 2026-04-25
Test Results Did QA pass? Any regressions? Passed all regression tests
