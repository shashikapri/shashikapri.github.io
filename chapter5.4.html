Chapter 5.4

How to Write a Scope Management Plan

US-20 Template · Process · Guidelines

A practical guide to creating a scope management plan that keeps your team aligned and your project on track.

Why a Scope Management Plan Matters

A well-written scope management plan is your project's rulebook. It prevents misunderstandings, provides clarity, and gives you a process to handle changes without chaos.

What is a Scope Management Plan?

The Scope Management Plan is a component of the overall project management plan that describes how the scope will be defined, developed, monitored, controlled, and validated. It doesn't define the scope itself—it defines the process for managing scope.

Step-by-Step: Writing Your Plan

STEP 01

Define the Scope Definition Process

Describe how you'll gather requirements and create the scope statement.

"Requirements will be collected through: interviews with key stakeholders, facilitated workshops, and analysis of existing documentation. The scope statement will include product description, acceptance criteria, and deliverables."

STEP 02

Define WBS Creation Process

Explain how you'll break down the work.

"The WBS will be created using a top-down approach. The project manager will facilitate a decomposition session with the team. Each work package will be small enough to estimate (max 40 hours). The WBS dictionary will contain descriptions, assumptions, and acceptance criteria."

STEP 03

Define Scope Validation Process

Specify how deliverables will be accepted.

"At the end of each sprint, the team will demonstrate completed work to the Product Owner. Formal acceptance will be documented in the Sprint Review. Any rejected items will go back to the backlog with feedback."

STEP 04

Define Scope Control Process

Establish how changes will be managed.

"All change requests must be submitted via the Change Request Form. The CCB will review weekly. Approved changes will update the scope baseline. Emergency changes may follow a fast-track process with post-approval."

Complete Template Example

SCOPE MANAGEMENT PLAN
Project: [Your Project Name] | Date: [Date] | Version: 1.0
1. Scope Definition Process

Requirements Gathering: The project team will conduct stakeholder interviews, surveys, and requirements workshops to collect all necessary requirements. The Product Owner will prioritize requirements based on business value.

Scope Statement Creation: The Project Manager will draft the scope statement including: project objectives, product scope description, acceptance criteria, and key deliverables. The scope statement will be reviewed and approved by all key stakeholders.

2. WBS Creation Process

Decomposition Approach: The team will use a deliverable-based approach to create the WBS. Major deliverables will be decomposed into work packages that can be estimated and assigned. The WBS will follow the 100% rule – all work must be included.

WBS Dictionary: Each work package in the WBS will have a corresponding entry in the WBS dictionary containing: description, acceptance criteria, assumptions, and estimated effort.

3. Scope Validation Process

Acceptance Process: At the end of each sprint, the team will present completed deliverables to the Product Owner during the Sprint Review. The Product Owner will verify that deliverables meet the acceptance criteria defined in the user stories.

Sign-off Requirements: Formal acceptance will be documented using the Acceptance Sign-off Form. Deliverables that do not meet acceptance criteria will be documented with feedback and returned to the backlog.

4. Scope Control Process

Change Control Board (CCB): The CCB consists of: Project Manager, Product Owner, Technical Lead, and a Stakeholder Representative. The CCB meets every Wednesday to review change requests.

Change Request Process: All change requests must be submitted using the Change Request Form. Requests will be analyzed for impact on timeline, budget, and resources. Approved changes will update the scope baseline and be communicated to all stakeholders.

Tips for an Effective Scope Plan

Keep it simple — Use clear, non-technical language
Tailor to project size — Small projects need less detail
Involve the team — Get input from those doing the work
Update as needed — The plan can evolve with the project
Get stakeholder buy-in — Review the plan with key stakeholders
Link to other plans — Connect with schedule, cost, and quality plans
Key Takeaway: A scope management plan doesn't need to be long or complicated. It just needs to clearly document HOW you'll define, validate, and control scope. Use the template above as a starting point and adapt it to your project's needs.
