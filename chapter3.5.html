Chapter 3.5

Working with User Stories and Scrum Boards

US-12 User Stories Scrum Boards

Master the art of writing effective user stories and using Scrum boards to track sprint progress.

Why This Matters for Team Members

User stories help you understand what the customer actually needs. Scrum boards help you see what everyone is working on. Together, they make sprint work clear, organized, and collaborative.

What are User Stories?

A User Story is a short, simple description of a feature written from the perspective of the person who wants it. It helps the team understand what to build and why [1].

As a [type of user], I want [some goal] so that [some reason].

Example: "As a project manager, I want to see all tasks in one place, so that I can track progress easily."

INVEST: Good User Stories

I - Independent

Can be developed in any order

N - Negotiable

Details can be discussed

V - Valuable

Provides value to user

E - Estimable

Size can be estimated

S - Small

Fits in one sprint

T - Testable

Can be verified

Example User Stories

Role Want So That
As a user I can log in with email I can access my account
As a shopper I can add items to cart I can buy multiple items at once
As a team member I can see my tasks I know what to work on
As a manager I can see team progress I can track sprint status

What are Scrum Boards?

A Scrum Board (or Kanban Board) is a visual tool that shows the status of all tasks in the current sprint. It helps the team see what's To Do, In Progress, and Done at a glance [2].

Example Scrum Board

To Do

Write user stories
Design database schema
Create wireframes

In Progress

Build login API
Write unit tests

Done

Setup project
Requirements document
Team onboarding
Cards move left → right Visual Progress Tracking

How to Use a Scrum Board

As a team member, you should:

1 Pick a task from To Do column
2 Move it to In Progress when you start
3 Move to Done when completed
4 Update board daily during standup

Best Practices for Teams

Keep stories small

Each user story should be small enough to finish within 1-2 days. If a story is too large, break it down [1].

Add acceptance criteria

Define when a story is "Done" with clear, testable acceptance criteria. This prevents confusion.

Update board daily

The board must reflect reality. Update task status throughout the day, not just during standup [2].

Speak up about blockers

Add a sticky note or tag to tasks that are blocked. The Scrum Master will help remove impediments.

Common Challenges & Solutions

Challenge: User stories are too vague or technical

Solution: Use the format "As a... I want... so that..." and involve the Product Owner in story writing [1].

Challenge: Team members forget to update the board

Solution: Make board updates part of the daily routine. Use digital tools that auto-save or send reminders [2].

Challenge: Cards get stuck in "In Progress" for days

Solution: Add WIP (Work in Progress) limits. If a task takes too long, break it into smaller pieces.

Summary: User stories help you understand WHAT to build and WHY. Scrum boards help you track HOW the work is progressing. As a team member, you contribute by writing clear stories and keeping your board updated daily.
